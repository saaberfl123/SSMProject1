### 3.3 核心业务规则（需求文档的骨头，验收就看这些）

**R1 下单规则**
- R1.1 产品必须存在且 `productStatus = 1`（上架），否则报"产品已下架"
- R1.2 `peopleCount` 必须是 1~10 的整数
- R1.3 提交的旅客数量必须**等于** `peopleCount`，否则报"旅客人数不匹配"
- R1.4 旅客必须都存在（`traveller.id` 有效）
- R1.5 下单自动生成 `orderNum`：`yyyyMMddHHmmss` + 3 位随机数（保证唯一）
- R1.6 新订单 `orderStatus = 0`（未支付），`orderTime = now`
- R1.7 订单总额 = `product.productPrice × peopleCount`（M2 新增 `totalPrice` 列）
- R1.8 **一次下单 = 写 2 张表（`order` + `order_traveller`），必须同一个事务**：任何一步失败全部回滚

**R2 取消规则**
- R2.1 只有 `orderStatus = 0`（未支付）的订单能取消
- R2.2 取消后 `orderStatus = 2`，**`order_traveller` 关联记录一并删除**（同事务）
- R2.3 只能取消自己的订单（`order.memberID == 当前登录会员 id`），否则报"无权操作"

**R3 登录规则**
- R3.1 账号 = `member.account`，密码**绝不明文存**：MD5 + 固定盐（或 BCrypt，阶段 6 再升级）
- R3.2 登录成功把 `member` 放进 `HttpSession`（key 定死 `LOGIN_MEMBER`）
- R3.3 未登录访问受保护接口 → 拦截器返回 `401` + 统一返回体 JSON（**不能**重定向到登录页，这是前后端分离的写法）

**R4 分页规则**
- R4.1 默认 `pageNum=1`，`pageSize=5`；`pageSize` 上限 50（防止有人传 100000）
- R4.2 返回体必须含 `total` / `pages` / `pageNum` / `list`（M4 之后包在 `Result.data` 里）

**R5 状态字典（写死成常量类，别散落在代码里）**

| 字段 | 值 | 含义 |
|---|---|---|
| `product.productStatus` | 0 / 1 | 下架 / 上架 |
| `order.orderStatus` | 0 / 1 / 2 | 未支付 / 已支付 / 已取消 |
| `order.payType` | 0 / 1 / null | 支付宝 / 微信 / 未支付 |

## 四、数据模型

### 4.1 现有表实测结构（连带坑一起记）

```sql
product(id PK AI, productNum int, productName, cityName, departureTime datetime,
        productPrice decimal(10,2), productStatus int)          -- 字符集 gbk
member(id PK AI, name)                                          -- 就两列
traveller(id PK AI, name)                                       -- 就两列
`order`(id PK AI, orderNum int, orderTime datetime, orderStatus int,
        peopleCount int, productID int, memberID int, payType int, orderDesc)  -- 保留字！
order_traveller(orderID int, travellerID int)                   -- 无主键、无索引
```

**注意 4 点**
1. `product` 表**没有 `productDesc` 列**，但 POJO 里有 → `select *` 时它永远是 null（M1 补列）。
2. `order.orderNum` 是 `int`，POJO 写的是 `String`；`order.orderTime` 是 `datetime`，POJO 是 `String` → 建议 M1 统一改成 `LocalDateTime` + `String`（jsr310 已就绪）。
3. 五张表都是 `gbk_chinese_ci`，应用走 UTF-8。现有数据是罗马音城市名（无中文），暂时不炸；**新建表/新列统一用 `utf8mb4`**，并在 URL 加 `&characterEncoding=utf8`。
4. `order_traveller` 没有主键 → 同一个人可能被重复添加。M2 补复合主键。

### 4.2 增量 DDL（可以直接复制执行，按里程碑分段）

```sql
-- ============ M1：补字段 + 加索引 ============
ALTER TABLE product ADD COLUMN productDesc varchar(500) NULL COMMENT '产品描述' AFTER productPrice;
ALTER TABLE `order` ADD COLUMN totalPrice decimal(10,2) NOT NULL DEFAULT 0 COMMENT '订单金额' AFTER peopleCount;
ALTER TABLE `order` ADD INDEX idx_order_member (memberID), ADD INDEX idx_order_product (productID);
-- order_traveller 补主键和索引（现有 4 行数据请先确认无重复）
ALTER TABLE order_traveller ADD PRIMARY KEY (orderID, travellerID);
ALTER TABLE order_traveller ADD INDEX idx_ot_traveller (travellerID);

  ADD COLUMN account   varchar(50)  NOT NULL DEFAULT '' COMMENT '登录账号',
```

### 5.2 XML mapper 的两条铁律

1. `namespace` = **DAO 接口的全限定名**，`<select id>` = **方法名**，一个字都不能错，否则启动就报 `Invalid bound statement`。
2. XML 放在 `resources/mapper/` 后，必须在 `RootConfig` 里告诉 MyBatis 去哪找（M1 第一步就是加这段）：

```java
@Bean
public SqlSessionFactory sqlSessionFactory(DataSource dataSource) throws Exception {
    SqlSessionFactoryBean bean = new SqlSessionFactoryBean();
    bean.setDataSource(dataSource);
    // ① 扫描 XML 映射文件
    bean.setMapperLocations(new PathMatchingResourcePatternResolver()
            .getResources("classpath*:mapper/*.xml"));
    // ② 打开驼峰映射 + 延迟加载（M1 用）
    org.apache.ibatis.session.Configuration cfg = new org.apache.ibatis.session.Configuration();
    cfg.setMapUnderscoreToCamelCase(true);
    cfg.setLazyLoadingEnabled(true);
    cfg.setAggressiveLazyLoading(false);
    bean.setConfiguration(cfg);
    return bean.getObject();
}
```

## 七、常见坑与排查手册

| 现象 | 大概率原因 | 处理 | 笔记章节 |
|---|---|---|---|
| 请求一直转圈不返回 | Druid 拿不到连接（驱动/账号/库名错），`maxWait=-1` 无限等 | 先单独用 JDBC 测连接；把 `maxWait` 设成 5000 让它快速失败 | MyBatis 13 |
| 报 `Invalid bound statement (not found)` | XML 的 `namespace` 或 `id` 与 DAO 对不上；XML 没被扫描到 | 逐字比对；确认 `mapperLocations` 路径 | MyBatis 2、12 |
| 查询返回对象但字段全是 null | `column` 与 `property` 没对上 / 没开驼峰映射 | 显式写 `<resultMap>`；开 `mapUnderscoreToCamelCase` | MyBatis 11 |
| 报错却看不到堆栈 | 日志只有控制台输出 | 加文件 Appender（5.4） | — |
| JSON 里日期是数组/报 500 | `LocalDateTime` 序列化 | 保持 jsr310 依赖；必要时 `@JsonFormat` | SpringMVC 8 |
| `@Transactional` 不生效 | 同类内部自调用 / 方法非 public / 异常被 catch 吞了 | 把事务方法提到 Service 外调用；或注入自身代理 | Spring 26 |
| 一条订单查询发了几十条 SQL | `@Many` 嵌套 select 的 N+1 | 改 JOIN + resultMap；或评估延迟加载 | MyBatis 23、25 |
| SQL 语法错误 | 表名 `order` 是保留字 | 一律写 `` `order` `` | — |
| 中文乱码 | 连接字符集 / 表字符集不一致 | URL 加 `characterEncoding=utf8`；新表用 utf8mb4 | — |
| 分页总数不对 | `PageHelper.startPage` 后面跟的第一条查询才被分页 | `startPage` 紧挨着目标查询写 | MyBatis 34 |
